# IP

> **Área:** [[05 - Networking & Internet/00 - Índice Networking - Internet|Índice Networking / Internet]] · **Concepto 2 de 25**

## Qué abarca
- Direccionamiento de dispositivos

## Mis notas
<!-- ai:start -->
## Objetivo
Utilizo la dirección IP para identificar de forma única a cada dispositivo que participa en una red IP, lo que me permite enviar y recibir paquetes de datos sin ambigüedad. Resuelvo problemas de conectividad cuando no se alcanza un host porque su dirección no está bien configurada o no pertenece a la subred esperada. En mi día a día como ingeniero de redes senior, la IP aparece en la configuración de routers, switches, firewalls y servidores, y es la base para diagnosticar rutas, aplicar ACLs y validar la asignación de direcciones mediante DHCP. Después de comprender cómo funciona el direccionamiento, puedo diseñar esquemas de subnetting, planificar la migración a IPv6 y depurar fallas de capa 3. Cuando trabajo exclusivamente con dispositivos de capa 2 o con enlaces que usan direcciones MAC, la IP deja de ser relevante.

## Esqueleto (el 20% esencial)
1. **Dirección única**: Cada host posee una IP que lo distingue dentro de una red IP.  
2. **Formato y versiones**: IPv4 usa 32 bits (p.ej. 192.168.1.10), IPv6 usa 128 bits (p.ej. 2001:db8::1).  
3. **Subnetting/CIDR**: La máscara de red delimita qué parte de la IP corresponde a la red y cuál a los hosts.  
4. **Resolución y asignación**: DHCP entrega IPs dinámicamente; ARP traduce IP a MAC dentro de la misma subred.  
5. **Ruteo**: Los routers usan la IP de destino para decidir el próximo salto según la tabla de rutas.

## Como funciona
1. Un dispositivo solicita una IP a través de DHCP (o usa una estática).  
2. DHCP responde con una dirección y la máscara de subred (CIDR).  
3. El host configura su interfaz con la IP y la máscara, y envía una petición ARP para obtener la MAC del gateway.  
4. Cuando el host envía un paquete, el stack IP encapsula los datos y coloca la IP de destino.  
5. El router recibe el paquete, consulta su tabla de rutas y reenvía el paquete al siguiente salto cuyo prefijo coincide con la IP de destino.  
6. El proceso se repite hasta que el paquete llega al host final, que lo entrega a la capa superior (TCP/UDP, HTTP, etc.).

## Detalles
- **Básico**: Comprender la notación decimal punteada (IPv4) y la representación hexadecimal (IPv6).  
- **Intermedio**: Aplicar CIDR para crear subredes eficientes; usar comandos `ip addr`, `ifconfig`, `netsh`.  
- **Avanzado**: Planificar migraciones a IPv6, diseñar VLSM (Variable Length Subnet Mask), implementar políticas de ruteo basadas en prefijos y usar técnicas de NAT.  

## Ejemplo minimo
```bash
# Obtener una IP vía DHCP y mostrarla
sudo dhclient eth0
ip -4 addr show dev eth0 | grep inet
```
Salida típica: `inet 192.168.1.45/24 brd 192.168.1.255 scope global eth0`  
El comando asigna una IP y la muestra con su máscara `/24`.

## Errores comunes
- **Confundir máscara y prefijo**: usar `255.255.255.0` cuando la red está configurada como `/16`.  
- **Duplicar direcciones**: asignar la misma IP estática a dos hosts, lo que genera colisiones.  
- **Olvidar ARP**: no actualizar la tabla ARP después de cambiar la IP de un dispositivo, provocando paquetes perdidos.  
- **Ignorar IPv6**: diseñar la red solo con IPv4 y quedar sin espacio al escalar.

## Estado actual
- **Fundamentos estables**: El modelo de direccionamiento IPv4/IPv6, el uso de CIDR y la operación de DHCP/ARP son pilares consolidados.  
- **Práctica moderna**: La adopción gradual de IPv6, la automatización de asignación mediante DHCPv6 y la integración de políticas de ruteo basadas en prefijos más largos (VLSM) son tendencias actuales en entornos empresariales y de proveedores de servicios.

## Conexiones
- **DNS**: traduce nombres de dominio a direcciones IP, permitiendo que los usuarios trabajen con nombres legibles en lugar de números.  
- **DHCP**: entrega automáticamente direcciones IP y parámetros de red, simplificando la gestión de grandes infraestructuras.  
- **Subnetting/CIDR**: define cómo se agrupan las IP en redes lógicas, optimizando el uso del espacio de direcciones y facilitando el ruteo.

## Ruta de estudio
1. **Prerequisitos**: conceptos de capa 2 (MAC, ARP), modelo OSI/TCP‑IP y comandos básicos de red.  
2. **Fundamentos**: estudiar IPv4, notación decimal, máscaras y CIDR; practicar con `ipconfig`/`ifconfig`.  
3. **Intermedio**: configurar DHCP, crear subredes con VLSM, usar `ping` y `traceroute` para validar rutas.  
4. **Avanzado**: migrar a IPv6, implementar DHCPv6, diseñar políticas de ruteo basadas en prefijos y explorar NAT64/DNS64.  
5. **Especialización**: automatizar asignación con herramientas como Ansible o NetBox, y profundizar en seguridad de IP (IPsec, ACLs).
